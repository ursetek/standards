What is a DR

A Decision Record (DR) is a short Markdown document that captures one decision, the context that forced it, and its consequences.

URSE DR is the URSETek standard for those documents. It defines two things and only two things:

  • the location where DRs are stored;
  • the file format of a DR.

Everything else — who approves a DR, whether a DR needs its own pull request, when a DR becomes binding, how statuses are enforced — is a project-level concern. URSE DR does not prescribe any of it.

Consolidation. This standard is currently Provisional. It will move to Consolidated once the URSETek RFC process is running and one or more RFCs ratify it. At that point a Consolidated by section will be added below.

Location

DRs live in the docs/dr/ directory at the root of the repository they belong to.

  • repository/
    • docs/
      • dr/
        • README.md
        • 000-dr.md
        • 001-<slug>.md
        • 002-<slug>.md

The README.md file is optional. If present, it MAY list the DRs of the project or point to this standard, but its content is not governed by URSE DR.

Cross-project decisions live in the organization-level URSETek/dr repository, following the same layout.

Format

Every DR is a Markdown file with the following sections, in this order:

  1. Title — # <short decision title>
  2. Status — Status: **VALUE** on its own line
  3. Context — the situation and the problem
  4. Decision — what was decided
  5. Consequences — what follows from the decision

Additional sections (Considered options, Rationale, References) MAY be added and are encouraged when they add information. The five sections above are the minimum.

URSE DR does not require a date in the document body. The date is always recoverable from version control history.

Numbering

DRs are numbered with an odd number of digits, minimum three. The number is part of the filename and is never reused.

Number Filename Meaning
000 000-dr.md Always: "Use URSE DR". The bootstrap record.
001 001-<slug>.md First project-specific decision.
002 002-<slug>.md Second decision, and so on.

The slug is lowercase, hyphen-separated, and describes the decision in two to five words. Example: 003-cross-document-references.md.

Future numbers MAY use five digits (00001) if a project expects more than a thousand DRs. The odd-count rule is preserved; the choice of three or five is project-level.

Status

Every DR carries exactly one status, written as Status: **VALUE** on its own line after the title. URSE DR defines the set of allowed values; their exact semantics and the process for changing them are project-level.

Value General intent
PROPOSEDWritten, not yet in force.
ACCEPTEDIn force for the project.
DEPRECATEDNo longer recommended.
SUPERSEDEDReplaced by a later DR.
REJECTEDConsidered and not adopted.

The value is uppercase. A project MAY define additional values if needed, but MUST support the five above.

Template

Copy this into a new file docs/dr/NNN-slug.md:

# <Short decision title>

Status: **PROPOSED**

## Context

<The situation and the problem. What forces are at play? What constraints
exist?>

## Decision

<What was decided. Be specific: name the chosen option, the APIs, the
formats, the boundaries.>

## Consequences

*   <What becomes true as a result.>
*   <What becomes harder or impossible.>
*   <What must be done differently from now on.>

Scope

URSE DR standardizes the following:

  • The directory where DRs are stored: docs/dr/.
  • The filename pattern: NNN-slug.md.
  • The section structure of a DR document.
  • The set of allowed status values.
  • The rule that 000-dr.md is always "Use URSE DR".

URSE DR deliberately does not standardize:

  • Who may create, approve, or reject a DR.
  • Whether a DR requires its own pull request.
  • How long a DR stays in PROPOSED.
  • Whether a DR is required before implementation.
  • Whether accepted DRs may be edited.
  • Any enforcement mechanism, automated or human.

These are project-level policies. A project using URSE DR documents its own process wherever it keeps its contributor guidelines.
